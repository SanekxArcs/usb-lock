# USB Lock

Невеликий Windows-застосунок: від’єднання довіреного USB-ключа або пристрою запускає відлік і штатне блокування Windows. Інтерфейс українською, WPF-UI, теми Windows 11, той самий набір компонентів, що й у `cursor-lang`.

## Запуск

Відкрийте `dist/USB-Lock-0.2.0/UsbLock.exe` або `Start USB Lock.cmd`. Пакет win-x64 містить .NET Runtime; встановлювати .NET окремо не потрібно. Переміщуйте **всю папку** `USB-Lock`, а не лише exe. Адміністратор не потрібен.

1. Під’єднайте знімну USB-флешку та виберіть її на сторінці «Захист».
2. Назвіть ключ, залиште серійну прив’язку або вимкніть її, натисніть «Створити ключ».
3. Натисніть «Увімкнути». Початково програма не озброєна.
4. Вилучення ключа запускає відлік. Повернення **цього самого** ключа скасовує його. Після завершення Windows блокує сеанс.
5. Для входу використовуйте Windows Hello або пароль Windows. Автоматичного входу через USB немає.

Програма не форматує флешку, не змінює її назву, не чіпає `.k3y` USB Raptor і не перезаписує наявний `.usb-lock.key`. Ключі USB Raptor несумісні. Якщо на флешці вже є наш файл, виберіть іншу або самостійно приберіть старий `.usb-lock.key`, якщо він більше не потрібен.

## USB-камера або інший пристрій (0.2.0)

1. На сторінці «Захист» у блоці «Додати джерело захисту» виберіть «USB-пристрій: камера, миша та інші».
2. Виберіть пристрій зі списку, за бажанням задайте коротку назву, натисніть «Додати пристрій».
3. Виберіть його у списку довірених і натисніть «Увімкнути». Від’єднання запускає відлік; повернення цього самого пристрою скасовує його.
4. Щоб перейти на флешку чи інший пристрій, вимкніть захист, виберіть інше довірене джерело й увімкніть знову.

Програма використовує SetupAPI для перевірки фізичних USB-пристроїв за точним Windows PnP instance ID. Складена камера з мікрофоном показується як один фізичний пристрій із назвами її функцій. Контролери й root hub не пропонуються; зовнішні USB-хаби можуть бути вибрані окремо. Нічого на периферію не записується, відео/аудіо не відкривається.

Для пристроїв без унікального ID Windows прив’язка може залежати від USB-порту. Це відображається поруч із пристроєм; після зміни порту може знадобитися додати нову прив’язку. Наявність унікального ID не є криптографічним доказом автентичності. Для бездротової миші з USB-приймачем відстежується приймач, а не живлення миші. Закриття програми камери не означає фізичного від’єднання.

У двох однакових пристроїв без власного серійного номера в тому самому порту ID може збігатися. Захист перевіряє присутність ID, а не секрет. Файл ключа на флешці залишається окремим режимом із перевіркою секрету.

Наявні ключі 0.1.0 зберігаються без ручної міграції. Імпорт/експорт налаштувань не переносить прив’язки пристроїв. Після запуску автоозброєння обирає перше під’єднане довірене джерело в порядку списку; ручне ввімкнення завжди поважає вибране джерело й не підміняє відсутній пристрій іншим.

## Щоденна робота

Закриття вікна згортає його в трей. Ліва кнопка на піктограмі відкриває вікно; права — меню захисту, ручного блокування та виходу. Вихід припиняє захист. Перед блокуванням з’являється відлік; за дозволом у налаштуваннях його можна скасувати з вимкненням захисту.

У налаштуваннях: затримка 0–3600 с, сповіщення, сигнал, запуск під час входу, запуск у треї, автоматичне озброєння після старту за наявності ключа, світла/темна/системна тема. Зміни застосовуються кнопкою «Зберегти». Імпорт показує параметри перед застосуванням. Експорт не містить довірених ключів, паролів або реєстрації автозапуску.

Зберігайте папку програми на постійному місці перед увімкненням автозапуску. Після переміщення відкрийте її з нового місця й збережіть автозапуск повторно. Перед видаленням вимкніть автозапуск і вийдіть із програми.

## Межі захисту

- Це користувацька програма, яка має працювати у вашому сеансі; не системна служба й не захист від адміністратора/Task Manager.
- Ключ має випадковий 256-бітний секрет; локально довіра містить SHA-256 відбиток. Налаштування шифрує DPAPI поточного користувача. Помилки DPAPI не переводять сховище у відкритий текст.
- Прив’язка використовує **серійний номер тому**, а не апаратний серійний номер USB. Форматування може змінити його, а цілеспрямоване клонування не виключене.
- Показуються накопичувачі, які Windows класифікує як Removable. USB SSD з типом Fixed у цій версії не підтримуються.
- Інтервал перевірки приблизно 750 мс плюс час доступу до пристрою. Затримка 0 означає блокування після виявлення відсутності, а не апаратну миттєву реакцію. Зависання драйвера може затримати перевірку.
- Відкликання видаляє локальну довіру, але залишає файл на USB. Прив’язка до поточного комп’ютера/користувача фактично забезпечена локальною реєстрацією й DPAPI; ключ не імпортується автоматично на іншому ПК.
- Дані: `%LOCALAPPDATA%\USB Lock\settings.dat` та `activity.log` (з ротацією приблизно після 512 КБ). Для навмисного скидання закрийте програму та перейменуйте папку даних; після цього потрібні нові ключі. Втрата USB не блокує звичайний вхід до Windows.

## Розробка і перевірка

Потрібні Windows та .NET 8 SDK.

```powershell
dotnet build UsbLock/UsbLock.csproj -c Release
dotnet run --project UsbLock.Checks -c Release
dotnet run --project UsbLock.UiCheck -c Release
./publish.ps1
```

`UsbLock.Checks` перевіряє стан захисту й валідацію ключів без блокування Windows. `UsbLock.UiCheck` відкриває тестове WPF-вікно, читає список USB без запису на них, рендерить сторінки в `artifacts` і завершується. Це перевірка компонування, а не доказ ручних взаємодій чи реального блокування. Вона також перевіряє DPAPI в окремій папці, якщо профіль виконання це дозволяє.
