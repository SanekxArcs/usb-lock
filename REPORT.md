# Оновлення 0.2.0 — USB-периферія

Додано режим «USB-пристрій: камера, миша та інші». Пакет: `dist/USB-Lock-0.2.0/UsbLock.exe`; спільний `Start USB Lock.cmd` відкриває цю версію.

- SetupAPI перелічує присутні фізичні USB-пристрої за точним PnP instance ID. Камера з аудіофункціями об’єднується під фізичним батьківським пристроєм; root hub та інтерфейси MI не дублюються у виборі.
- Додавання/назва/відкликання використовують те саме захищене сховище, що й файли ключів. Старі записи без типу лишаються файловими ключами.
- Від’єднання активного пристрою запускає відлік і запит блокування; повернення з тим самим ID скасовує відлік. Інша під’єднана довірена флешка чи камера з іншим ID не підміняє вибраний пристрій.
- Трей, відлік, журнал, відновлення після сну й автоозброєння охоплюють обидва типи джерел. Активне джерело та його назва показуються у статусі. Помилки переліку пристроїв означають відсутність джерела, а не дозвіл продовжувати захист із невідомим станом.
- Доступу до відео/аудіо чи запису на периферію немає. Для пристроїв без унікального ID показано примітку про прив’язку до порту. Присутність ID не є криптографічною автентифікацією: однаковий пристрій без серійного номера у тому самому порту може мати той самий ID.

Перевірки: **44 автоматизовані перевірки успішні**; зокрема старий JSON, точне й нечутливе до регістру зіставлення ID, відсутній/відкликаний вибір, заборона підміни іншим джерелом, від’єднання й повернення камери. Живий read-only перелік SetupAPI знайшов **6 фізичних USB-пристроїв**. WPF-рендери нового режиму оглянуто у світлій/темній темі й розмірі 880×640 (`artifacts/usb-devices*.png`). Release build успішний.

Фізичне від’єднання камери та фактичне блокування Windows не виконувалися агентом. WPF-рендери не є перевіркою фізичних кліків. DPAPI у sandbox досі недоступне через незавантажений профіль; його перевірка явно пропущена, незашифрованого fallback немає. NuGet audit UI-перевірки недоступний через мережу (NU1900).

Для ручної перевірки: додайте вебкамеру, виберіть її та ввімкніть захист із затримкою 10 с; від’єднайте й поверніть до завершення відліку. Повторіть із завершенням відліку та звичайним входом Windows. Якщо стара версія вже працює, вийдіть із неї через трей перед запуском 0.2.0; налаштування зберігаються.

Технічні джерела: [SetupDiGetClassDevs: лише присутні пристрої](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetclassdevsw), [USB identifiers і composite devices](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/standard-usb-identifiers).

# Звіт про USB Lock 0.1.0

Реалізовано 29.10.2026 у новій папці `usb-lock`, без змін у `cursor-lang` або USB Raptor. Скриншоти використано як опис функцій, а не як інструкції до виконання.

## Основне

Готовий автономний пакет Windows x64: `dist/USB-Lock-0.1.0/UsbLock.exe`. Він містить .NET Runtime. Головна функція: випадковий ключ на знімному USB → локальна довіра → озброєння → вилучення саме активного ключа → відлік → `LockWorkStation`. Повернення ключа скасовує незавершений відлік. Фактичне блокування підтверджується подіями сеансу Windows, а не лише результатом API.

Інтерфейс WPF-UI 4.3.0, як у `cursor-lang`: штатний заголовок, Mica, округлені картки, системний акцент, світла/темна/системна тема, бічна навігація. Українська мова. Три сторінки: захист, налаштування, журнал/довідка.

## Можливості зі скриншотів

| Група USB Raptor | Стан у USB Lock |
|---|---|
| Створення файлу ключа, вибір USB | Реалізовано власний формат `.usb-lock.key`; старі файли не перезаписуються |
| Пароль шифрування ключа | Замість спільного пароля — випадковий 256-бітний секрет і SHA-256 відбиток локально |
| Декілька ключів | Створення, назви, локальний список і відкликання; озброєння прив’язане до конкретного ключа |
| Прив’язка до USB | Опційний серійний номер відформатованого тому; не апаратна автентифікація |
| Ключ лише цього ПК | Потрібна локальна реєстрація; довіра захищена DPAPI користувача; експорту довіри немає |
| Затримка, таймер | Єдиний зрозумілий відлік 0–3600 с; повернення ключа скасовує його |
| Дозвіл скасувати | Є; скасування також вимикає захист |
| Звуки/сповіщення | Опційні Windows-сповіщення та системний звук перед блокуванням |
| Автозапуск, запуск у треї, автоозброєння | Є; вимкнені початково; автоозброєння чекає на довірений ключ |
| Ручне блокування з трея | Є, також кнопка на головній сторінці |
| Імпорт/експорт | Є для несекретних параметрів; імпорт показує попередній перегляд до збереження |
| Звітність | Локальний журнал подій з ротацією та переглядом останніх 100 записів |
| Кольори/рандомізація власного lock screen | Не реалізовано: використовується штатний захищений екран Windows |
| Автоматичне розблокування USB | Не реалізовано; для входу Windows Hello/пароль |
| Додатковий PIN/пароль після USB | Не реалізовано; автентифікацію виконує Windows |
| Пароль на налаштування, служба захисту процесу | Відкладено; програма не заявляє стійкість до користувача або адміністратора |
| Master-key/backdoor | Пропущено; не потрібні для звичайного входу Windows |
| Синхронізація ПК, receiver, Telegram, serial bridge | Пропущено як окремі інтеграції зі значно більшим обсягом |
| Запуск довільних програм/команд | Пропущено |
| Mute, вимкнення дисплея, insomnia | Пропущено |
| Перейменування тому, info-файл, донатні обмеження | Пропущено |
| Перемикання мов | Український інтерфейс; додаткові мови відкладено |

## Перевірки та обмеження доказів

- Release build і self-contained publish: успішно, без помилок чи попереджень у збірці застосунку.
- 26 автоматизованих перевірок стану й ключів: успішно. Покрито вилучення/повернення, затримку, скасування, нульову затримку, повторну спробу після помилки, неправильний ключ, неправильний том, пошкоджені дані та імпортовані параметри.
- WPF-вікно сконструйовано і відрендерено: усі три сторінки, світла/темна тема, мінімальний розмір 880×640. PNG у `artifacts`. Це програмний RenderTargetBitmap, не знімок живого робочого столу та не доказ Mica/DPI/фізичних кліків.
- Під час перевірки виявлено наявний знімний накопичувач F:. Нічого на нього не записано; USB Raptor не змінено.
- DPAPI roundtrip **не перевірено**: профіль sandbox повертає `CryptographicException` про відсутній завантажений профіль користувача. У звичайному сеансі це потрібно перевірити першим створенням ключа. Перед записом на USB програма перевіряє можливість захищеного збереження. Незашифрований fallback відсутній.
- Інструмент Windows Computer Use не надав доступу до вікна, запуск завершився тайм-аутом дозволу. Ручні кліки, трей, фізичне вилучення/вставлення USB, автозапуск після входу, сон/відновлення й фактичне блокування Windows **не перевірені**.
- Під час відновлення залежностей UI-перевірки NuGet audit був недоступний через мережу (NU1900). Це не перевірка безпеки залежностей. Публікація використовує встановлені пакети; аудит для цієї офлайн-команди було вимкнено.

## Коротка ручна перевірка

1. Відкрити `dist/USB-Lock-0.1.0/UsbLock.exe` у звичайному сеансі Windows, створити ключ на USB. Перезапустити й переконатися, що ключ розпізнано.
2. Увімкнути захист із затримкою 10 с; вилучити USB і повернути до завершення. Перевірити скасування.
3. Повторити вилучення, дочекатися блокування, увійти через Windows Hello/пароль, повернути ключ.
4. Перевірити скасування, інший USB, відкликання, сон/відновлення, закриття в трей та вихід.
5. За потреби ввімкнути автозапуск і автоозброєння, перевірити після повторного входу у Windows.

[Microsoft: LockWorkStation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-lockworkstation) пояснює асинхронність запиту та необхідність входу користувача після блокування. [Microsoft: GetVolumeInformation](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationw) описує серійний номер тому, який призначає ОС під час форматування.


Під час фінальної публікації виявлено запущену попередню збірку з `dist/USB-Lock`, яка утримує DLL. Її не зупиняли. Остаточні файли опубліковано поруч у `dist/USB-Lock-0.1.0`; `Start USB Lock.cmd` указує на них. У прочитаному журналі також є записи про створення ключа й скасування відліку після повернення USB; ці дії не виконувалися автоматизованою перевіркою агента й не замінюють перевірку фактичного блокування.
